1 背景与目标

本章回答：为什么从「聚合监控」走向「自营交易」，以及本迭代要解决的具体问题。

1.1 现状（已确认事实）

游盯盘当前是多平台游戏账号交易聚合监控工具：聚合交易猫、盼之代售、螃蟹账号、7881、DD373、5173 共 6 个平台、11 款在售游戏的账号商品，提供统一检索比价、上新/降价监控、价格走势与收藏；合并版已具备「游拍卖」担保支付、卖家钱包提现与付费会员的资金托管基础设施。产品合规声明为「仅做信息聚合展示，不参与交易、不提供担保」。

1.2 问题

观察到的问题影响的用户与时机产品回应（本迭代）
供给不可控：在售商品全部来自第三方平台，平台无法保证账号真实性与卖家履约买家在下单与交接环节，最大顾虑是「买后被找回」卖家自营上传 + 实名与归属凭证审核（FR-A）
定价无锚点：账号只有挂牌价，买家无法判断贵贱买家浏览与比价决策时大模型估值与性价比排序（FR-B）
信任靠承诺：高价值账号仅凭商品描述难以建立信任买家下单前犹豫、放弃交易时鉴号专家人工鉴定（FR-C）+ 找回包赔（FR-D）
交接靠私聊：改绑、验号、放款流程无标准与留痕买卖双方交接期，纠纷高发且无证据AI 客服全程介入监管并固化证据链（FR-E）

1.3 目标（可观察结果）

  • 卖家可在平台内完成「上传账号 → 生成标准化商品图 → 审核上架 → 售出提现」的完整闭环，无需依赖第三方平台发布。
  • 买家在商品列表可按性价比排序，在详情页可见估值区间、性价比分与依据说明，并能自主选购找回包赔、申请鉴号。
  • 每一笔自营订单从下单到确认收货全程有 AI 客服引导与节点留痕；发生账号被找回时，买家可在线提交理赔，平台按规则先行赔付并向卖家追偿。
  • 平台从「不参与交易」转为「交易组织方与担保方」，相应合规声明、协议文本与资质要求同步更新（见 5.6）。

2 范围

按最小完整旅程圈定 P0；跨平台分发等依赖外部能力的项为 P1。

2.1 P0 主旅程

卖家实名+归属凭证→ 上传账号（一键生成截图）→ 平台审核→ 上架+估值展示→ 买家按性价比选购→ 下单（可选包赔/鉴号）→ 担保支付→ AI客服引导交接→ 确认收货→结算

入口条件：卖家已通过实名认证与账号归属凭证审核。完成证据：买家点击「确认收货」后资金划入卖家钱包、商品状态变为「已售出」、订单进入可理赔期。恢复路径：① 交接失败 → 订单退款关闭（FR-A6）；② 售后被找回 → 理赔流程（FR-D3/D4）。

2.2 P1 支持能力

  • 一键打通其他交易平台分发（FR-A8）：向交易猫/7881 等已授权渠道推送卖家商品。受第三方平台开放能力制约，P1 先交付「渠道素材包一键复制」，API 直连按渠道逐个评估。
  • 鉴号专家工作台（FR-C3 的接单侧仅做最小后台，完整工作台 P1）。

2.3 明确不做（防止分歧）

  • 不做账号租赁、代练、陪练等非交易业务；不自建 IM App（沿用订单内嵌会话）；不做站外收款通道（所有资金走既有担保支付与钱包）。
  • 估值结果不作为成交价承诺，也不用于自动定价（仅展示与排序）。

4 功能需求

4.1 模块 A：卖家上传与买家购买

FR-A1实名与账号归属凭证 P0

目的：把「卖家是谁、账号是不是他的」前置固化，是包赔与追偿的证据基础。

触发：注册用户首次点击「我要卖号」时强制进入资质流程。

材料要求校验
实名认证姓名 + 身份证号 + 人脸核验 核验服务商 TBD与提现银行卡持卡人一致，不一致禁止上架
账号归属凭证（至少 1 项）账号注册时间页 / 首次充值账单 / 实名认证页 / 常用登录设备截图，须含可识别的账号标识人工审核为主（SLA 24h [假设]），凭证与商品填报的区服/等级冲突时驳回

结果：通过后获得卖家资质（按游戏维度生效 [假设] 全局生效还是按游戏生效 TBD）；驳回可见原因并无限次重提。例外：凭证审核通过但后续被证实非本人账号 → 冻结卖家钱包与全部在售商品，进入运营处理（见 5.5 审计）。

FR-A2商品发布表单 P0

字段（必填项缺失不可提交）：

字段类型/约束说明

区服 / 平台渠道游戏模板枚举（如微信区/QQ区；官服/B服）与估值输入联动
账号标识文本，仅卖家与成交后买家可见列表与详情页一律脱敏展示
结构化资产按游戏模板：段位/等级、皮肤数、英雄/角色数、关键资产清单（可多选典藏/限定项）估值（FR-B）与截图生成（FR-A3）的数据源

售价 / 是否支持包赔≥1 元；支持包赔为默认勾选 [假设]不支持包赔的商品在列表带风险提示标识

FR-A3一键生成账号截图（标准化展示图） P0

目的：把卖家随手上传的原始截图合成为统一模板的商品展示图，提升列表一致性与防盗图能力。

触发：发布表单素材齐备后点击「一键生成」；生成不替代卖家上传原图，原图仍留存。

处理规则：以 FR-A2 的结构化资产字段 + 卖家原始截图为输入，按游戏模板输出成套展示图（默认 4 张：主图卡、资产总览、关键资产、段位/等级页）。每张合成图强制包含：① 属性条（区服/渠道 + 模板关键数值）；② 平台水印与编号「游盯盘 NO.{listingId}」；③ 防盗提示文案「交易请认准游盯盘担保流程」。一致性约束：展示图数值取自结构化字段，与商品详情同源，禁止手工改图字段；卖家可对单张图选择「仅用原图」。

结果：生成图进入商品图组并随 Listing 送审；原图与生成图均保留至订单证据链归档（见 5.5）。

规则：运营后台按「凭证一致性 → 资产字段与截图相符 → 描述合规」三级清单审核；通过后 Listing=在售，触发 FR-B 首次估值；驳回必须从预设原因库选择并附文字说明，卖家可修改重提。例外：同一卖家 24h 内被驳回 ≥3 次 → 暂停其发布入口 72h [假设]，防恶意刷审。

FR-A6账号交接流程 P0

触发：订单进入「已支付(托管)」后由 AI 客服（FR-E）自动开启标准交接六步；买卖双方也可在任一步申请退款关闭。

  1. 协议与费用确认（含包赔协议双方签署状态核验）
  2. 卖家在订单会话内提交账号资料（密码/绑定信息），系统时间戳留痕
  3. 买家改密、换绑手机/邮箱，并回传改后凭证截图
  4. 买家按商品图组核验资产；可加购鉴号（FR-C2）
  5. 买家点击「确认收货」（或到期自动确认 TBD，见 3.2）
  6. 平台结算：扣佣金 费率 TBD 后划入卖家钱包，Listing=已售出

例外：任一环节卖家 24h[假设]无响应 → AI 客服提醒并通知运营；买家发起「交接失败退款」需勾选原因，卖家 48h 内可申诉，无申诉或申诉失败 → 全额退款、Listing 回「在售」或按责任下架。

FR-A7买家购买记录与售后入口 P0

「我的购买」列表展示订单状态、交接凭证、估值快照（下单时点的估值区间与性价比分，固化不可变）、包赔协议与理赔入口（理赔期内显示）。估值快照是理赔与纠纷的基准材料之一。

FR-A8一键打通其他交易平台分发 P1

目的：卖家在本平台发布后，一键把同一商品分发到其他游戏交易平台扩大曝光。

处理规则：① 卖家在「渠道授权」中绑定第三方平台账号（登录态托管 方式与合规评估 TBD）；② 平台按各渠道规范自动重组素材包：标题（渠道字数限制）、图片（渠道尺寸模板，复用 FR-A3 生成图）、价格、结构化描述；③ 具备发布能力的渠道由采集适配器反向复用做自动代发布，不具备的渠道提供「复制素材包」一键粘贴；④ 本平台改价/下架时向卖家推送同步提醒，不自动修改第三方平台在售价 [假设]。

例外：渠道风控拦截代发 → 降级为素材包模式并明示；分发产生的第三方平台成交与本平台无关，订单页需展示该边界声明。

4.2 模块 B：大模型估值与性价比

FR-B1估值输入与输出 P0

触发：Listing 首次审核通过自动估值；卖家改价、资产字段变更、同游戏成交样本新增时重估 重估频率上限 TBD，建议每日 1 次。

输入（全部来自平台已有数据，不新增采集）：结构化资产字段（FR-A2）、同游戏同区服近期本平台成交样本、聚合在售商品同款挂牌价分布 样本冷启动量不足时的兜底策略见 Q4。

输出：估值区间 [低, 高]、中点值、性价比分、置信度（高/中/低）、依据说明（列出主要影响的 3–5 个资产因子与参考样本数）。置信度规则：可比样本 ≥20 → 高；5–19 → 中；<5 → 低。

FR-B2性价比分计算 P0

设 R = 估值中点 ÷ 当前挂牌价：

规则定义
性价比分score = min(100, round(R × 70))。即挂牌价=估值中点得 70 分；低于估值约 43% 及以上封顶 100 分 系数 70 为初始参数，上线后校准
参与排序条件仅置信度为「高/中」的商品参与性价比排序；「低」置信商品显示区间但性价比分位置标「样本不足」
取整与展示区间取整到元；分数整数；每次展示附估值时间

边界声明（强制展示）：估值为模型参考，不构成价格承诺；卖家不因估值低于挂牌价被强制改价。

FR-B3按性价比排序与筛选 P0

商品市场现有排序（最新/最低价/降价）新增「性价比」档：按性价比分降序，同分按上架时间倒序；与游戏 tab、平台 chip、价格区间筛选正交可叠加。卡片上以徽标显示分数（≥85 显示「超值」标签 [假设] 阈值）。

交互示意 · 排序切换（点击体验）
商品挂牌价估值中点性价比

FR-B4详情页估值卡 P0

商品详情页价格下方固定估值卡：区间、中点、性价比分、置信度、依据说明（因子贡献 + 参考样本数）、估值时间与免责声明。买家可点「解读」展开模型自然语言说明（大模型生成，≤200 字，仅基于已展示数据，不得引入未验证外部信息）。

4.3 模块 C：鉴号专家

FR-C1专家入驻 P0

流程：申请（实名 + 该游戏资历证明：段位/账号资产/交易履历截图）→ 运营考核（试鉴定 2 单 [假设]）→ 签约入驻（含保密与责任条款）。专家按游戏维度授权，可被暂停/清退。专家不得接自己名下或关联主体上架商品的鉴定单。

FR-C2买家申请鉴定 P0

触发：① 下单前在详情页点「申请鉴号」；② 交接中由 AI 客服在核验步骤提示加购。两处均进入同一鉴号单流程。

5 共享规则

5.1 资金与结算

  • 所有自营订单资金走既有担保支付托管；结算触发点 = 确认收货（手动或自动）；顺序：扣佣金 → 入卖家钱包；包赔费与鉴号费独立记账、不进入卖家结算。
  • 赔付资金池：来源为包赔服务费计提 计提比例 TBD + 卖家保证金 机制 TBD；池余额与出账全部运营可见。

5.3 脱敏与可见性

账号标识、区服外的登录信息在列表/详情/报告一律脱敏；原始凭证与生成图组仅订单相关方与运营在证据链内可见；估值依据说明不披露其他成交买家的任何信息。

5.4 内容风控（复用聚合侧能力）

商品描述与会话消息统一过「站外联系方式/私下交易话术/违规代练」检测；命中即按 FR-E3 或发布拦截处理。

5.5 审计与留存

Listing 审核记录、协议签署流水、证据链、理赔裁决记录留存 ≥3 年 按法务要求校准；裁决类操作（审核、理赔、封禁）双人复核制 [假设]。

5.6 合规边界（本迭代的立场变更）

产品决策：自营交易上线后，现行「仅做信息聚合，不参与交易、不提供担保」声明必须废止并替换为平台交易组织方声明。上线前需完成：① 协议文本律师审定；② 「包赔」命名与话术规避保险牌照问题（FR-D1）；③ 游戏厂商用户协议对账号交易的风险评估与应对口径 Q7；④ 未成年人交易限制条款；⑤ 电子签与实名核验供应商合规评估 Q8。任一项未完成，对应功能保持灰度。
