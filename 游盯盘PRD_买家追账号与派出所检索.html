1. 背景与目标

游戏账号交易的行业性痛点是「卖家找回」：账号完成交接、货款结算后，卖家利用实名信息、注册证件或客服申诉渠道将账号找回，买家钱号两失。游盯盘现有防线为：卖家实名 + 归属凭证（模块 A）、货款托管与六步交接留痕（模块 B/C）、找回包赔（模块 D）。

但包赔覆盖不了全部场景：未勾选包赔的订单、损失超出赔付上限的订单、以及买家除退款外还想追究卖家责任的订单，买家在现实中缺少两条关键能力：

  • 不会告：不知道起诉书怎么写、去哪个法院、需要准备什么证据；账号买卖纠纷标的多在数百至数万元，多数买家不值得付费请律师。
  • 不会报：卖家找回行为在司法实践中可能构成盗窃罪或诈骗罪（以实名制信息秘密取回已售账号），但买家不清楚该去哪个派出所报案、带什么材料、找哪个窗口。

产品决策：平台把「交易时已沉淀的合同、实名、交接、聊天证据」转化为维权弹药，提供两条闭环：

账号被找回
→
平台一键生成起诉书（模块 F）
→
指引网上立案 / 跟踪进展
账号被找回（涉嫌刑事）
→
检索管辖地派出所（模块 G）
→
生成报案材料包
→
线下/线上报案

目标（可观察结果）

  • 买家在订单页发起维权后，无需任何法律写作能力即可获得一份要素齐全（当事人、诉讼请求、事实理由、证据清单、管辖法院建议）的民事起诉书文件。
  • 买家可按省/市/区、关键词或地图位置检索到派出所的地址、联系电话、值班窗口与管辖说明，并一键获得与该派出所匹配的报案材料清单。
  • 平台在起诉与报案两场景中仅提供文书生成与信息指引，不作出法律结论、不代办诉讼与报案（见第 6 章合规边界）。

关键失败恢复路径

  • 找回申报核验不通过（证据不足）：给出补证清单与重新提交入口，不阻断包赔/申诉等其他通道。
  • 卖家实名信息缺失或失效（历史订单）：起诉书被告信息降级为「姓名+身份证号+户籍地址待补」，并提示买家可向法院申请调查令，文书中如实标注来源。
  • 派出所数据检索无结果：回退展示该区县级公安局信息并提示反馈纠错。

状态流转仅由「买家动作 + 平台裁决」驱动；平台不校验法院/公安结果的真实性，买家回填内容一律标注「买家自述」。

4. 功能需求 · 模块 F 买家追账号维权

FR-F1P0找回事件申报与平台核验

目的：把「账号被找回」从口头纠纷变成有记录、有证据、有处置的维权案。

入口：已完成担保订单详情页新增「账号被找回？发起追账号维权」按钮；订单完成后 365 天内可发起 TBD（时限需法务确认与诉讼时效衔接）。

申报字段：

字段类型规则
找回时间日期时间必填；不得晚于当前、不得早于订单完成时间
找回情形单选实名被改 / 绑定手机邮箱被换 / 客服申诉找回 / 密码被改 / 其他（文字说明 ≤200 字）
损失金额数字默认取订单实付金额，可修改（≤ 实付金额 + 后续充值凭证合计）
是否已尝试联系卖家单选是（附站内聊天记录）/ 否（提示先走订单会话）
自证材料图片/视频选填 ≤20 个；登录异常截图、客服申诉回执、账号实名页等
诉求类型多选民事起诉 / 刑事报案 / 先走找回包赔（勾选包赔时联动模块 D，见 6.4）

核验规则：提交后维权案进入「待核验」；客服 48 小时内 TBD（SLA 待定）完成核验，核验动作包括：调取交接日志、比对账号绑定变更记录、向卖家发起 24 小时申辩（卖家逾期未回应视为默认）。核验通过 → 「已立案」，同时冻结卖家钱包余额与提现（金额上限=损失金额，见 6.3）；核验驳回 → 展示原因与补证清单。

异常：同一订单重复申报 → 阻断并跳转已有维权案；订单处于包赔理赔中 → 允许并行申报但文书中注明「已获赔付金额」，避免双重受偿；卖家已注销账号 → 实名存档仍可调取，正常受理。

FR-F2P0电子买卖合同存档与调取

目的：起诉书的「合同依据」必须来自交易当时签署的文本，而非事后拼凑。

规则：

  • 每笔担保订单支付成功时自动生成《账号买卖合同》（PDF，含双方姓名、身份证号脱敏段、手机号、账号标的（区服+掩码）、价款、支付时间、六步交接约定、找回责任条款、送达地址确认条款、管辖条款）。
  • 合同文本采用平台固定模板 + 订单变量填充；签署方式为「下单页勾选同意 + 支付即生效」，勾选记录（时间戳、账号）随单存档。
  • 合同只读存档于订单与维权案，双方均可在各自订单页下载；维权案生成文书时系统直接引用存档合同编号与关键条款。
  • 历史订单（本功能上线前成交、无存档合同）：以「交易快照」替代合同，文书中如实标注「无书面合同，依据平台交易快照」。

管辖条款默认文本：「因本合同发生的争议，双方同意由合同履行地（买家收货/使用地）或被告住所地人民法院管辖；标的额符合小额诉讼程序的，适用小额诉讼程序。」TBD（条款措辞由法务终审，格式条款效力风险见 6.5）。

FR-F3P0证据包自动归集

目的：起诉/报案最耗时的是整理证据，平台把交易全程留痕一次打包。

归集清单（自动拉取 + 买家补充，详见 6.1 统一证据包规范）：合同、支付流水、交接六步日志、账号归属凭证（卖家入驻时上传）、订单会话记录、找回申报与自证材料、卖家实名信息、平台《交易存证证明》。

结果：生成带页码与哈希校验码的证据包 PDF；证据包编号写入起诉书「证据清单」章节。买家可勾选剔除个别材料，剔除项在文书中如实留痕。

FR-F4P0起诉书一键生成

目的：核验通过后，买家在维权案内点一次「生成起诉书」即得到可递交的民事起诉状。

生成流程：

系统预填八要素
→
买家确认/修改事实陈述
→
AI 润色「事实与理由」
→
法务规则引擎校验
→
预览 → 导出 PDF/Word

八要素预填规则：

要素来源可编辑性
原告信息买家实名（姓名、身份证号、住址、电话）可修改（提示以身份证为准）
被告信息卖家实名存档（姓名、身份证号、户籍/居住地址、注册手机号）只读 + 补充项（其他联系方式）
诉讼请求默认：① 返还购号款 ¥X；② 赔偿损失 ¥Y（充值/鉴定费等，买家填报）；③ 诉讼费由被告承担可增删改，金额联动证据
事实与理由交易时间线 + 找回事件 + 合同条款引用，AI 依据证据包生成叙述稿可编辑；编辑后重新过规则校验
证据清单证据包编号自动填充随证据包勾选联动
受诉法院建议管辖引擎（见下）给出 1-3 个候选法院及理由可改选；自由填写时提示核实
送达地址确认买家填写并电子签名确认必填
落款签名买家姓名 + 日期；导出后需本人手写签名后递交 TBD（电子签名效力由法务确认）—

管辖引擎规则：按「被告住所地 → 合同履行地（买家所在地）」顺序输出候选；两地跨省级时并列展示并说明选择后果（立案便利 vs 送达周期）；标的额 ≤ 各省小额诉讼上限时提示适用小额诉讼程序（一审终审、周期短）。

法务规则引擎校验（生成前后各跑一次）：必填要素完整；金额与证据勾稽（诉请金额 ≤ 证据合计）；禁止出现侮辱性、定性刑事结论（如「被告构成盗窃罪」）等表述，命中则阻断并提示改写；文书尾部自动附加「本文书由平台依据交易存证辅助生成，内容经原告确认，最终是否立案以人民法院审查为准」。

异常：AI 服务不可用 → 降级为纯模板填充（事实与理由使用固定句式），功能不中断；买家修改后重新生成保留历史版本。

FR-F5P1立案指引与维权进度跟踪

  • 文书就绪后展示递交指引：人民法院在线服务（微信小程序）网上立案步骤、现场立案材料清单（起诉书 N 份、证据包、身份证明）。
  • 买家回填「立案号/受理号 + 进展节点」（立案、缴费、调解、开庭、判决、执行），每节点带时间戳形成维权时间线，向买家与客服展示。
  • 判决获赔后引导买家登记结果；卖家账户冻结按「已结案」裁决解除或划扣（划扣给买家需法院生效文书 TBD，平台不自行划扣）。
  • 180 天无进展 → 提醒并自动转「已关闭」，保留重新发起入口。

FR-F6P0平台协助出证（交易存证证明）

目的：以平台名义向法院/公安证明交易真实性与交接过程。

  • 维权案「已立案」后买家可申请《交易存证证明》，客服 3 个工作日内出具：载明订单号、双方实名核验结果、支付流水号、六步交接日志摘要、合同编号，加盖平台电子签章 TBD（电子签章供应商待定）。
  • 文书编号可在平台验证页验真（输入编号+校验码）。
  • 法院/公安依法调取时按取证流程提供原始日志，不受买家申请限制。

5. 功能需求 · 模块 G 全国派出所信息检索

FR-G1P0派出所数据入库与更新

目的：建立可检索的全国公安派出所公开信息库，为报案场景提供准确的「去哪里报」。

字段必填说明
派出所名称是规范全称，如「XX市公安局XX分局XX派出所」
省 / 市 / 区县是标准行政区划三级编码
详细地址是含门牌；附经纬度（地图检索用）
联系电话是官方对外公布的值班/户籍窗口电话；无则标注「以 110 转接为准」
对接警官/窗口否仅收录官方公开的社区民警姓名与警号（警务公示信息）；未公开则显示「社区警务队（现场对接）」 TBD（可公开范围需数据合规评审）
管辖范围否文字描述辖区；用于报案指引推荐
服务时间否24 小时接警 / 窗口工作时间
来源与更新时间是每条记录带来源（官网页面/政务开放数据）与采集时间；超过 12 个月标记「待核实」

数据来源：各地公安机关官网、政务服务网、公安开放数据平台等公开渠道采集 + 管理员后台人工校对入库 TBD（首批覆盖城市范围与采集方式另行评审；禁止抓取需授权数据，遵守 robots 与法规）。

更新：管理员可批量导入（CSV）与单条编辑；用户纠错反馈生成工单，管理员核实后发布新版本并保留历史。

FR-G2P0派出所检索

  • 入口：全站导航「报案指引」独立页；维权案内「选择报案派出所」步骤；派出所详情可跳转回维权案。
  • 检索方式：① 行政区划逐级筛选（省→市→区县）；② 关键词（派出所名称/地址片段）；③ 地图模式：按当前位置显示周边派出所及距离（需买家授权定位，拒绝授权则仅用列表模式）。
  • 智能推荐：从维权案进入时，依据「案发地（买家账号使用地）/ 被告住所地」预置筛选条件，并展示推荐说明：「网络盗窃/诈骗案件一般由犯罪行为发生地或结果发生地公安机关管辖，建议优先选择您所在地（作为被骗结果发生地）派出所咨询报案」TBD（表述由法务确认，仅作一般性指引）。
  • 结果列表：名称、区县、地址、电话、距离（地图模式）、更新时间徽标；空结果回退展示同级区县公安局条目并提供纠错入口。

FR-G3P0派出所详情页

  • 展示 FR-G1 全部字段；电话一键复制/拨号（移动端 tel: 链接）；地址复制与地图导航跳转（外部地图 App）。
  • 「该所报案提示」：是否 24 小时接警、需携带证件、经济类报案一般找哪个窗口（值班民警/经侦联络）——仅展示该所公开信息，不做承诺性表述。
  • 「信息有误？」纠错按钮：提交后生成工单，详情页显示「已反馈，核实中」。

FR-G4P0报案材料包生成

目的：把起诉链路同款证据复用为报案格式，解决「报案说不清楚」。

  • 维权案中选择「刑事报案」诉求后，可选定目标派出所并生成《报案材料包》PDF：① 报案陈述模板（事情经过按时间线预填，买家修改确认）；② 交易证据摘要（合同、支付流水、交接日志、存证证明编号）；③ 被报案人（卖家）信息页：姓名、身份证号、注册手机号、平台账号 ID——来源标注「平台实名核验存档」；④ 损失金额与计算依据。
  • 报案陈述模板尾部固定提示：「报请公安机关依法处理；本人对所述事实真实性负责。」买家确认后生成。
  • 同步展示线上报案/求助渠道指引：110、反诈专线 96110、国家反诈中心 App（仅列官方渠道，不做跳转承诺）。
  • 无维权案的用户也可生成「精简版材料包」：仅基于订单导出证据摘要，实名信息按 6.2 隐私规则脱敏。

FR-G5P1维权案与派出所联动

  • 报案材料包生成后，维权案状态推进节点增加「已递交材料（回执号回填）」；公安受案/不予立案结果由买家登记，平台据此联动 FR-F4（不予立案时可转民事起诉文书生成）。
  • 「刑民并行」提示：同一事实已刑事报案的，起诉书事实部分自动注明报案情况，避免法院以刑拒立 TBD（衔接规则由法务确认）。

6. 共享规则与合规边界

6.1 统一证据包规范

  • 证据条目字段：序号、名称、来源（系统存档/买家上传）、生成/取得时间、内容摘要、SHA-256 校验码。
  • 系统存档类证据（合同、流水、交接日志、会话）由平台保证来源可溯；买家上传材料标注「买家提供，平台未核实」。
  • 同一证据包在起诉书与报案材料包中复用同一编号体系，避免两份文书证据清单不一致。

6.2 实名数据使用与隐私

  • 卖家身份证号、住址等仅在维权案（已立案）场景向买家展示，用途限定为「司法文书当事人信息」；文书与页面均附提示：「上述信息系平台实名核验存档，仅可用于本次维权，不得用于骚扰、公开传播等非法用途」。
  • 无维权案导出材料时，对方身份证号按前 4 后 4 脱敏。
  • 买家查看对方实名、生成文书、下载证据包均写入操作审计日志（谁、何时、哪笔订单、何种动作）。
  • 卖家可申诉「信息被冒用」，客服核实期间冻结相关文书下载。

6.3 冻结与资金联动

  • 维权案立案 → 冻结卖家钱包余额与提现申请，冻结上限 = 买家申报损失金额；卖家提交申辩可提前解冻（客服裁决）。
  • 平台不因维权案自行划扣任何资金；划扣仅凭法院生效文书走线下执行流程。
  • 维权案关闭/结案 → 按裁决解除冻结，通知双方。

6.4 与找回包赔（模块 D）的关系

  • 已勾选包赔的订单：买家可先走理赔；理赔获赔后发起维权案时，诉请默认调整为「平台代位追偿」提示 TBD（代位求偿主体与话术由法务确认），或买家就未覆盖损失部分继续起诉。
  • 同一损失不得双重受偿：文书生成时自动带入「已获赔付 ¥X」并在诉请中扣减展示。

6.5 合规边界（产品红线）

  • 平台非法律服务机构：所有文书为「辅助生成的草稿」，页面与文书均声明不保证立案结果；禁止出现定罪、量刑类结论性表述（规则引擎强制拦截）。
  • 管辖条款等格式条款需显著提示并单独同意，避免被认定无效；上线前法务逐条评审模板。
  • 派出所信息仅收录公开数据，展示「来源+更新时间」；警官个人信息仅限警务公示范围，若无法合规获取则整列不展示。
  • 报案指引不得表述为「报案一定能立案」；涉刑事建议统一引导 110/96110/国家反诈中心 App。
  • 未成年人交易、外挂账号等违规订单：维权案受理时校验订单合规性，违规订单转风控处理，不生成文书 TBD（处置口径待定）。
